The research day is the market-start UTC day. The claim is relative to explicit immutable source bytes. It does not describe every historical venue listing, prove that an omitted market was never listed, or imply uninterrupted quotes, price persistence, an actual first threshold crossing, or sender execution. Preserve older contracts/blocker checkpoints and identify the new completeness scope explicitly in day/window manifests and consumer verification. For every identity in M(G,D), reconcile all mapping/resolution evidence in G and retain exact native winner-token/label provenance. Later publication can resolve that dependency only in a new source/day generation. Preserve every qualifying retained observation with a stable locator including object/product identity and row ordinal, exact source event and receipt integers, selected witness and available witness set/sequence. Deterministic serialization order is distinct from evidence sufficient to order qualifications. Different witness clocks do not become comparable receipt clocks, and a global sort by local sequence does not create venue order. No compression may erase a later recorded receipt merely because its ask repeats. A null ask is a recorded source null with unknown reason; no row for a side is no recorded observation in G. Closure evidence should count every required product and decoded/projected/rejected row, bind classifications and all day dependencies, and account for missing/invalid work explicitly. No current partial UTC day is promoted. Upstream capture-loss findings and Audit Partial labels must remain visible, but do not automatically disprove a complete projection of already published rows. ### Inventory membership and immutable pinning

1. **Incomplete parser evidence can still be called complete.** `parse_page()` accepts recognized relative hour links and `/v3/?page=N` links, but silently ignores other hour-like links and alternate pagination forms. Absence of a recognized next link becomes terminal without a separately validated terminal/total contract. `_read_pages()` checks uniqueness and reverse ordering, which are useful but do not prove all links were recognized. Preserve raw page bytes or equivalent fully reproducible parsing evidence, explicit per-page hours/terminal state, and reconcile any advertised counts/pagination. Validate actual dates/hours, not just a digit-shaped path. The current output stores hashes and sizes without the raw page evidence needed to replay its membership derivation after the source changes.

2. **Parsed manifests are not independently bound to their claimed raw hash.** The inventory stores parsed objects and an observed raw-manifest hash; `validate_inventory()` verifies only the digest shape, hour relation and outer generation. It cannot recompute the raw hash, and does not validate required products/object sizes/paths/ranges when loading an inventory. Preserve the exact raw manifest or an explicit independently checkable raw-to-normalized binding and validate the full supported manifest contract. The resulting inventory may legitimately be an acquisition-time composite of individually pinned objects; do not imply a source transactional snapshot that was never obtained.

3. **Unchanged discovery is not idempotent.** Generation identity excludes `discovered_at`, while the immutable published payload includes it. A repeated unchanged discovery therefore creates different bytes under the same generation tag. Reuse the already sealed inventory payload or make identity and payload treatment of volatile acquisition metadata consistent.

### Complete product and classification accounting

4. **Target-like lifecycle rows can disappear silently.** `mapping_record()` returns `None` for a noncanonical slug, so `mapping_shard()` records no error for cases such as a malformed target 5m slug that fails the model regex. The exception path records only a narrow asset-prefix/`5m` test and silently drops other malformed rows. Neither path records a complete out-of-scope/ambiguous classification denominator. Add explicit classifications and counts/provenance; reconcile alternate/null target-like metadata and contradictory question/slug identity. The existing slug classifier also does not independently check question identity. Unknown BBA/resolution condition references are currently ignored rather than counted/reconciled.

5. **Partition identity does not prove the executed hour set.** Both shard entry points check that the supplied partition ID exists somewhere in the plan, but do not check that the supplied `chunk` hours equal that partition's exact planned hours. A valid ID with a shortened chunk can publish a partial report under a complete partition identity. Catalog/data-index aggregation checks the reported ID and inventory generation but not exact hours, per-hour required product hashes, decoded row counts or all projected/rejected row accounting. Consequently `complete_expected_partition_set=True` is stronger than the checked evidence. Recompute the exact request-to-plan binding and reconcile every expected hour/product/count before setting closure true. Check actual decoded event types, not only footer statistics. A missing per-day asset must be accepted only when the verified partition report establishes zero projected rows for that day, rather than unconditionally skipped.

6. **Cross-generation reuse and recovery are inconsistent.** Mapping IDs omit inventory generation, but catalog rejects reused mapping reports from a different inventory generation. Data IDs include the whole catalog generation, causing every BBA source range to be reacquired when any catalog content changes. Chunk membership also shifts if an older hour is inserted before existing boundaries. Use stable content-based acquisition/projection identities and explicit new-generation binding proofs, so unchanged successful products survive append/remerge and unrelated mapping changes. Separate acquiring immutable depth-free product projections from joining them against a particular catalog when necessary. Bind the actual transform implementation identity; an unchanged string constant alone cannot distinguish changed transformation code.

### Canonical requirements and daily claims

7. **Read-time schema and relational validation is insufficient.** The flat field allowlists are valuable, but validators do not fully enforce scope version, integer/range clock and ordinal fields, actual UTC-hour validity, asset/outcome/token identity, or corresponding mapping relations. For example, the observation validator's price regex accepts `1.9999`; the constructor rejects it, but a consumer must not rely on the constructor having run correctly. The consumer does not reconcile each quote token/side/interval and official winner against the corresponding unique mapping, detect all conflicting duplicate mappings/winners, or recompute all declared generation/count bindings. A certificate requires independent validation of those relations, not only content hashes and presence of both side labels.

8. **Evidence requirements need explicit policy and persisted reasons.** `certify_day()` requires a non-null ask on each side, although complete inventory projection and faithful explicit unavailability are separate concepts. If this is the intended additional research eligibility rule, state it as such; it is not evidence of source completeness. The method itself has no past-UTC-day check, relying only on caller scheduling. Its computed `reasons` list is printed but absent from the durable manifest. Persist exact exclusion/pending reasons, and make direct certification fail closed for a partial current/future day. Missing selected-witness information must be represented under an explicit permitted unknown-clock rule or rejected; it must not acquire unstated timing semantics.

9. **A deterministic artifact tie-break is not lawful event order.** `market_signal()` correctly fails closed when earliest qualifying source timestamps tie across outcomes. Within one outcome it selects by source file/row ordinal even if tied qualifying rows have different prices or incompatible receipt witnesses. That is a reproducible representative selection, not evidence of which recorded observation was first. Return an explicit equivalent/ambiguous tie result, or resolve only using supported same-clock provenance. Never label an arbitrary artifact-order winner as a uniquely earliest observation.

### Promotion and autonomous continuation

10. **Current authority is updated before independent verification.** `window()` publishes and invokes `_update_current()` before the workflow's consumer-verification job. Every referenced object and required semantic relation must verify before changing current. The reviewed function also iterates release asset dictionaries as `name` and calls `name.endswith()` when locating `manifest_sha256`, which raises instead of constructing the window. These are concrete publication defects.

11. **Scheduled discovery does not establish durable backlog continuation.** The workflow's six-hour schedule, standard Linux runners, bounded parallelism and `fail-fast: false` are appropriate. However, every run discovers another inventory, rather than explicitly resuming an unfinished pinned generation; the reuse defects above then obstruct recovery. All chunks and days are emitted directly into matrices without a durable bounded queue or demonstrated continuation beyond matrix limits. Persist the active inventory and exact missing work, resume it on scheduled runs, and bound each run's matrix with an explicit remaining-work checkpoint.

12. **The failed-new-day/current rule is not established.** Window selection uses certified days from the new catalog/index only. A failed new day can still lead to a different window of surviving days and a current-reference update. Comparing only the latest day, count and inventory discovery time does not prove unchanged-current behavior or full membership monotonicity. Test the actual old/new certified sets, source revisions, concurrent late workers and failed additions against the declared policy before promotion.

These findings require implementation repairs and meaningful targeted verification. They do not justify weakening the source scope, importing a different dataset, or reviving the earlier venue-census/continuity requirements. No production source rows or workflows were executed by this reviewer during this code review.
