# Independent target-first salvage review

Two independent read-only reviews challenged the target-first path. They acquired no
source data and changed no files.

## Source authority

The source review confirmed that the pinned first-party responses support the exact
6,048-member returned cohort and authoritative aligned UP/DOWN token orientation. It
rejected calling the 170,369 unidentified V3 conditions unrelated: current catalog
responses do not exclude a deleted, moved, relisted or null-dated target from that set.
The precise missing fact is whether any unidentified condition changes target
membership within the retained V3 generation. Historical catalog closure is one
sufficient solution; direct positive identity/exclusion closure is the narrower one.

## Implementation

The implementation review found that the tentative consumer trusted a day manifest's
own source-asset list rather than independently reconstructing the complete day shard
set from all 116 pinned index partitions. It also found missing strict manifest and
cross-pointer checks, duplicate-row validation after dictionary collapse, a null-start
target omission, no scheduled incremental path, and an equal-day current-reference
race. Those findings make the tentative day/window Releases non-authoritative even for
the narrower returned-cohort product.

The final fail-closed audit verified that current certification, window publication and
consumer verification reject before source/API access; the null-start omission is
fixed; the salvage workflow is absent; `observed-current` is absent; and the status and
README reject every tentative output. Re-enabling authority requires both the source
membership condition and a repaired independent consumer verifier.
