# Independent catalog enumeration evidence

The successful access scout at commit f9207e78a7a23218fe5aa262bd1336fd0f5792d5
establishes usable Gamma and historical CLOB metadata access. It does not establish
exhaustive expected membership. Old source and continuity proofs remain preserved.

This next manual, standard-Linux workflow records fourteen independently durable,
bounded catalog streams: the full requested series scope in ascending and descending
ID order, and market/event keyset streams with explicit closed true/false for each
of the three prior canary dates (August 25, 27 and 28, 2026). End-date slices extend
through the following 00:05 UTC boundary. They are boundary diagnostics, not yet
market-start-day catalogs. Each stream is capped at 50 pages of 100 entries and
64 MB of response bytes. Exhausting a cap is never terminal pagination evidence.

Only explicit first-party metadata fields survive response projection. Prices,
winning results, depth, volumes and arbitrary payloads are discarded before
publication. Entire projected streams and small deterministic summaries are sealed
as content-addressed immutable Releases. Existing valid stream assets are read and
verified before source access; successful streams survive sibling failure. This is
stream-level recovery, not a claim of durable individual pages before upload.

Both source and independent implementation review approved this as evidence-only
acquisition. Pagination validation checks exact request/cursor chains, page counts,
row totals, duplicates and terminal/error accounting. All reports explicitly deny
catalog certification and research authority.

The complete preserved series inventory must be classified, including unnamed or
renamed candidates; the summary's asset-word and slug matches are diagnostics only.
Unfiltered series requests do not themselves prove the server includes all lifecycle
states. Inspect returned flags and source semantics. Ascending/descending agreement
compares stable identity fields, not live values. Full date-free target-series
history and independent handling of null/moved dates, duplicate/relisted identities,
listing exceptions and exact interval/token labels remain required. No theoretical
288-slot schedule and no V3-observed denominator is authorized by this workflow.
